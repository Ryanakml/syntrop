# Planning

Inspect the relevant goal, current projects, tasks, dependencies, and constraints. Separate outcomes from actions: a task should have a clear completion condition under the user's control. Build near-term milestones and the next executable tasks; keep distant work directional until evidence improves. Order prerequisites explicitly and avoid a dependency graph that leaves every next action blocked.

Use `life project add`, `life task add`, and `life task depends add` only when the user has committed to the plan or asked to create it. Read back the project, dependency readiness, and next task; run `life validate`. Do not add tasks solely to make a plan look complete. Surface dependencies, unknowns, and a meaningful next action.
