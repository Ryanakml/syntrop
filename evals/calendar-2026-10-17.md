## Adversarial findings corrected

- External extras such as attendees/location could survive a sparse patch. Changed managed event updates to full replacement (`PUT`) with ETag checks and read-back verification.
- The same sparse-patch issue retained old colors or timed start fields when the intended representation removed them. Regression tests cover palette fallback and timed-to-flexible replacement.
- Offset timestamps were compared as strings for cancellation. Compare actual instants, or workspace-local exclusive dates for all-day markers.
- Initial habit-display configuration time could override later deactivation time and erase prior reminder history. Inactive lifecycle uses its own update time; only explicit display removal uses display-change time.
- Callback state alone did not validate Host/absolute-form origin. Exact loopback Host/origin now required; hostile callbacks cannot consume a pending valid authorization.
- Disconnect could race an active connect/sync. It now shares the local operation lock, and tests confirm active authorization cannot silently undo a reported disconnect.
- Minimal provider tombstones can omit private properties. Stable event IDs still detect deletions when mappings are lost; explicit recovery uses a distinct deterministic replacement ID and converges.
- Downloaded Desktop JSON can contain Google's older official authorization URI. It is accepted from a fixed allowlist and normalized to the current fixed authorization endpoint; arbitrary endpoints are rejected.

No known critical authentication or synchronization defect remains from these reviews, but unavailable live evidence leaves residual integration risk. Whole-series changes may affect historical displayed occurrences under provider series semantics. Edited recurring-instance exceptions remain conflicts requiring resolution in Google, even with `--resolve local`. The integration is manual, one way, and does not infer habit completion.

## Live verification still required

Follow the [beginner OAuth guide](../docs/integrations/google-calendar.md). After the owner creates a Desktop client and consents, use a disposable synthetic workspace and dedicated test calendars. Verify first/repeated sync, move, cancel, manual drift, selected recurring habit, timezone, and optional free/busy from actual Google responses. Inspect the actual Google/mobile/Notion view where available. Clean only disposable resources created for that test. Do not publish the owner's real schedule until its event titles/counts and privacy mode are separately reviewed and authorized.

This beta can disclose missing live evidence; it must not be described as fully verified or production-ready. ICS snapshot export is deferred to keep this milestone focused on authenticated manual synchronization.
