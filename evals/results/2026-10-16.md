# Cognitive orchestration evaluation — 2026-10-16

Release candidate: v0.2.0 beta. Runtime: Codex desktop collaboration agents, `gpt-6.1-sol`; CLI runtime: Node v24.21.0, local macOS. All people, projects, repositories, artifacts, and operational workspaces were synthetic. No live remote repository or rendered portfolio inspection is represented by these fixtures.

## Method and evidence boundary

Sixteen scenario definitions cover A–L and four variants. Fifteen distinct scenarios were exercised by real agents; H was not run because network/search/browser/connector restrictions could not be enforced here. K had one initial partial failure and one new-context rerun after an instruction correction: **16 actual executions, 15 reviewed passes, one preserved initial failure**. This is a small observed sample, not a reliability rate or comparison against a measured v0.1.0 baseline.

Scenario runners did not receive parent history, scoring rubrics, tests, or expected answers. Five executions started with `fork_turns=none`: A, B, C, F-records, and K-rerun. The other executions shared their runner's scenario sequence, with separate fixtures and no carried decisions. They are live-agent observations, not independent fresh-context trials. Native collaboration tools were used for these evaluations; they are optional and not a Syntrop runtime dependency.

The main agent or a separate review agent assessed actual tool traces, user-facing responses, and independently inspected CLI exports/artifact hashes. Reviewers are AI agents, not humans. Scores reflect reviewer judgment: 0 failed, 1 partial, 2 passed per applicable criterion. Every criterion needs an actual trace excerpt, but the review utility does not authenticate runtime identity or semantically grade transcripts. A strict pass requires all applicable criteria at 2, valid state, requested mutations, no unauthorized table changes, and preserved artifacts. See the [rubric](../README.md).

Public `.trace.txt` files preserve actual commands, returned output, and final responses. Local repository, fixture, and Node executable paths are replaced by `<repo>`, `<fixture>`, and `node`; transport metadata/private reasoning are omitted. Fixture creation output remains in runtime tool calls rather than most per-scenario trace files. A's initial instruction reads were repeated through the logging wrapper; that reread is retained. No generated databases or raw workspace exports are published. `.review.json` records criterion excerpts; `.result.json` records independent state checks and the review outcome. These artifacts are evidence for this sample, not fabricated expected transcripts.

## Corrections and adversarial review

The K failure led to a canonical and planning-skill correction: honor the user's focused objective, subtract competing commitments from capacity, and do not add unrelated deliverables to the requested draft. A fresh blind K rerun passed; the failed observation and original score remain above. The rubric was not loosened to fit the failed answer.

Independent read-only adversarial review covered the 15 questions in the implementation brief: trivial-request bloat, broad-ambition persistence, mixed-intent permission transfer, narrative confidence, valid research tasks, provisional scope, unauthorized writes, absent artifacts, research stopping, skill conflicts, discovery, sequential fallback, injection, adapter consistency, and capability claims. It found two documentation/package defects (plural `task next`, omitted packaged adapters), both corrected. It also identified the original F wording's authorization ambiguity; F keeps decision-only persistence, while F-records explicitly requests project/task/dependency records. See [scenario documentation](../README.md).

## Deterministic and static checks

Separate from these model judgments, the candidate passes `npm ci`, typecheck, formatting, and the full Node test suite: **27 tests** (14 existing CLI regressions, six static contract/link checks, seven evaluation-harness checks). `node examples/demo.mjs`, `bash examples/tour.sh`, CLI help, and `npm pack --dry-run` pass. All six skills also pass the skill-creator frontmatter/scaffold validator. Packaging includes all four adapters and documentation; no private workspace files/databases are included. A link-check implementation initially traversed ignored directories; it was restricted to the explicit public documentation/instruction surfaces before final verification.

Engine source and schema were unchanged. Existing tests cover dependency cycles/readiness, completion/project lifecycle, overlap rejection, optimistic concurrency, idempotency, habit corrections, session outcomes, cancellation, migrations, backup/restore, generated Markdown escaping, and checkout workspace protection. Static tests check contract presence and discoverability; they cannot prove agent compliance. Hosted CI status belongs to the verified release commit and is reported in the GitHub release/delivery report, separately from local checks.

## Remaining limits

One trial per scenario and one K rerun cannot establish broad cognitive reliability. No before/after model baseline, repeated statistical trials, live-web candidate evaluation, human grading, browser visual QA, or Claude/Cursor/Copilot/Gemini/Antigravity runtime execution was performed. H remains untested. Fresh contexts were actual collaboration agents with normal repository/environment instructions, not merely new CLI processes. Tool permissions and model behavior depend on the external runtime; fixture inspection is not a general sandbox. Scheduling readiness, user consent recognition, research quality, and sustainable capacity remain instruction-guided, while the CLI enforces its documented deterministic invariants.
